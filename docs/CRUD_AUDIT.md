# 메뉴별 등록·수정·삭제 점검 결과 (2026-10-26)

화면이 쓰는 서비스(`src/Neosys.Local.Core/Services/*Service.cs`)를 임시 SQLite DB에 대고
메뉴마다 **3건 등록 → 목록·상세 확인 → 1건 수정 → 1건 삭제 → 목록 2건**을 확인하고,
딸린 행(소유자·메모·희망지역·연동·첨부)과 `X_hist` 이력, 업무일지 자동집계까지 봤다.
점검 시나리오는 테스트 `src/Neosys.Local.Tests/CrudAuditTests.cs`(12건)로 남겼다. 화면 버튼으로 같은 일을 한 결과는 아래 "화면 점검" 절.

- 운영 DB·운영 서버·실제 사용자 DB는 쓰지 않았다(테스트마다 임시 DB 파일).
- 화면에서 `GetAsync`가 null을 돌려줄 때는 이미 처리한다(`SchedulePage.cs`의 `OpenRowAsync`, `VendorPage.cs`의 `OpenAsync`).

## 고치지 않은 것 (확인 필요)

| 항목 | 내용 | 비고 |
| --- | --- | --- |
| 실제 삭제의 이력 작성자 | `DELETE` 이력의 `changed_by`는 지워진 행의 마지막 수정자(`OLD.upd_id`)다. 직원 A가 등록하고 B가 삭제하면 A의 삭제로 집계된다 | SQLite 트리거는 세션 값을 모름. 고치려면 삭제 직전에 `upd_id`를 갱신해야 하는데, 그러면 'U' 이력이 1건 더 생긴다. 한 PC 여러 직원 사용 여부에 따라 결정 |
| 상담 중복 저장 | 상담관리에서 등록한 상담의 연락처가 고객 구입자 전화와 같으면 고객 상담이력용 사본이 1건 더 생겨(`ct_interview.INS_LINKED`) 목록에 2건으로 보이고, 1건을 지워도 사본은 남는다 | 기존 시스템과 같은 동작(기존 테스트 `OtherMenuScenarioTests.상담관리_5건`에 기록됨) |

## 물건 삭제 시 연동 정보 확인 (2026-10-26 추가)

물건 등록창·목록(행 우클릭 [삭제]) 모두 `Views/Properties/PropertyDelete.cs`에서 같은 순서로 묻는다.

1. 삭제 방식: [예] 과거데이터(이력)로 저장한 뒤 삭제 / [아니오] 영구히 삭제 / [취소]
2. 연결된 일정(사용중)이나 사진·평면도가 있으면: "연결된 일정 N건·사진·평면도 M건이 있습니다. 연동 정보도 삭제할까요?"
   [예] 함께 삭제(일정은 남기고 물건 연결만 끊음, 사진·평면도는 사용안함) / [아니오] 연동은 남기고 물건만 삭제 / [취소] 삭제하지 않음.
   연동이 없으면 1번만 묻는다. 여러 건을 고르면 건수를 합쳐 한 번만 묻는다.

| 연동 삭제 | `Sql/Procs/pt_sale.DEL_LINKS.sql` → `PropertyService.DeleteAsync(ptNo, saveHistory, deleteLinks)` |
| 물건 삭제(딸린 행만) | `Sql/Procs/pt_sale.DEL.sql` — 연동은 건드리지 않음 |
| 테스트 | `CrudAuditTests.물건_3건_수정_삭제`(연동 함께 삭제), `물건_삭제_연동은_남기기`(남김·삭제된 일정은 세지 않음) |

## 화면 점검 (2026-10-26)

디버그 빌드의 새 점검 모드 `--crud`(`src/NeosysLight/DevCrud.cs`)로 메뉴 창을 실제로 띄우고,
[등록] → 입력칸에 값 입력 → [저장]을 눌러 메뉴마다 3건을 등록한 뒤 목록에서 1건을 골라 [삭제]하고 확인 질문에 '예'로 답했다.

```bash
NEOSYS_DB=<점검용.db> NEOSYS_FILES=<임시 폴더> src/NeosysLight/bin/Debug/net8.0-windows/NeosysLight.exe --crud 결과.txt [메뉴키]
```

- 데이터: 빈 점검용 DB(임시 폴더)에서 시작. 사용자 실제 DB 경로면 실행하지 않는다. 운영 서버는 부르지 않고 법정동·단지 목록만 가짜 서버(견본: 서울 강남구 개포동·대치동, 단지 '점검자이')로 답한다.
- 상담모드 설정이 켜져 있어도 점검 중에는 메모리에서만 끄고(설정 파일 저장 안 함) 기본 화면으로 본다.
- **한계**: 사용자 PC 화면을 마우스·키보드로 조작하는 도구가 없어, 앱 안에서 버튼의 `OnClick`(실제 누름과 같은 처리)을 호출하고
  입력칸은 컨트롤 값(글자·선택 항목·체크·표 셀 편집)으로 넣었다. 키 입력·포커스 이동·마우스 위치 같은 실제 입력 장치 동작은 점검하지 않았다.
  메시지 상자는 띄우지 않고 내용을 기록한 뒤 '예'로 답했다. 물건 삭제의 연동 질문을 보기 위한 일정 1건은 서비스로 연결했다.
- 입력칸은 `FormBuilder`가 붙인 `AutomationId`(= DB 컬럼 키)로 찾는다(접근성 도구에도 쓰이는 표준 속성).
