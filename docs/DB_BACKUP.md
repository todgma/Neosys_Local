# 로컬 DB 관리 — 계정별 DB · Neosys 공유폴더 분산 백업 · 복구 · 대표 조회

2026-10-27 요청 → 2026-10-28 설계·1~5단계 구현 → 2026-10-29 사용자 구성안("DB 백업 및 공용폴더 사용 관련 구성안")에 맞춰 폴더 구조와 설정 화면을 바꿨다.

## 요구사항

1. 메인 서버 없이 사무실 네트워크의 공유폴더로 DB를 관리한다.
2. 로그인 성공 후 **로그인 계정 이름으로 DB 파일**을 만들어 쓴다. 직원은 자기 DB만 쓴다.
3. 이 PC와 등록된 공유폴더 **모두에 일자별로 백업**하고 7일치만 보관한다. PC 한 대가 고장 나도 다른 곳의 사본으로 복구한다.
4. 대시보드 설정(톱니) 버튼 옆 **DB 아이콘 버튼**에서 설정·백업·복구를 한다.
5. **대표만** 직원 DB를 골라서 볼 수 있다(보기만).
6. (2026-10-29) PC마다 같은 모양의 `Neosys\<계정>\BackUp` 폴더, 파일 이름 `<계정>_yyyyMMdd.db`, 네트워크 공유 설정·드라이브 선택·3분할 화면, 작업 스케줄러 백업.

## 결정됨

- 2026-10-28: 대표는 직원 DB를 **보기만** 한다(읽기 전용). 수정·합치기는 하지 않는다.
- 2026-10-29 (구성안 질문 4개, 모두 권장안):
  1. [공유설정]은 **관리자 권한 확인 창(UAC)을 띄워 프로그램이 직접** 켠다.
  2. 지금 쓰는 **DB 원본은 공유 밖**(`%LOCALAPPDATA%\Neosys\accounts\<계정>`)에 두고, 공유되는 Neosys 폴더에는 계정별 BackUp만 둔다. 다른 사람이 공유 권한으로 내 DB 원본을 지우거나 덮어쓰지 못하게 하기 위해서다.
  3. 작업 스케줄러 백업을 켜면 **주기 백업만** 스케줄러로 넘긴다. [지금 백업]과 종료 시 백업은 프로그램에 남긴다.
  4. 예전 구조(`Neosys\<사무소번호>\<계정>\yyyy-MM-dd.db`) 백업은 **새 구조로 옮긴다**(로그인할 때 자동).

- 공유폴더의 DB 파일을 여러 PC가 **직접 열어 쓰면 안 된다.** 네트워크 폴더에서는 SQLite 잠금을 믿을 수 없어 DB가 깨진다. 공유폴더는 백업 보관용이고, 작업은 각 PC의 로컬 DB에서 한다.

## 1. 계정별 DB

구현: `Data/AccountStore.cs`, `AppServices.OpenAccountAsync`, `LoginWindow.OpenLocalAsync`, 테스트 `AccountStoreTests`.

- DB 원본: `%LOCALAPPDATA%\Neosys\accounts\<계정ID>\<계정ID>.db`, 첨부: 같은 폴더 `files\`. 계정 ID 중 파일 이름에 못 쓰는 문자는 `_`.
- 시작 순서: 서버 로그인(DB 없이) → 계정 DB 열기·생성·마이그레이션 → 공통코드 → 대시보드. 로그아웃 후 다른 계정이면 그 계정 DB로 바꾼다.
- 첫 로그인 때 예전 단일 DB(`neosis_local.db`)가 있으면 그 계정 DB로 옮길지 묻는다.
- 계정 폴더에는 `backup_status.json`(백업 상태), `session.json`(마지막 로그인 정보 — 작업 스케줄러 백업용), `backup.lock`(백업·복구 잠금)도 둔다.

## 2. Neosys 폴더 분산 백업

구현: `Core/Services/BackupService.cs`·`BackupLock.cs`, `App/BackupScheduler.cs`, 테스트 `BackupServiceTests`.

### 폴더 구조 (PC마다·공유폴더마다 같음)

```
<Neosys 폴더>\                     이 PC: C:는 %LOCALAPPDATA%\Neosys\Shared, 다른 드라이브는 X:\Neosys
  ├─ <내 계정>\BackUp\              네트워크에는 \\PC이름\Neosys 로 공유
  │    ├─ <계정>_20261029.db        그날의 마지막 백업(하루 1개, 같은 날은 덮어씀)
  │    ├─ <계정>_20261029.json      정보: 계정·rtNo·offNo·이름·PC·백업 시각·DB버전·크기·SHA-256
  │    ├─ <계정>_20261028.db … (보관 일수만큼)
  │    ├─ latest.json
  │    └─ files\                    첨부 미러(.deleted\yyyyMMdd\ = 지운 파일 임시 보관)
  └─ <다른 PC 계정>\BackUp\…        다른 PC가 이 PC 공유로 보낸 백업
```

- 등록한 공유폴더 경로는 그 안의 Neosys 폴더로 해석한다(`BackupService.ShareRoot`). `\\PC\Neosys`는 그대로, `\\PC\D` 같은 경로는 `\\PC\D\Neosys`를 쓴다.

### 백업 순서

1. 계정 잠금(`BackupLock`, `backup.lock` 독점 열기)을 얻는다. 프로그램·작업 스케줄러·복구 중 다른 작업이 돌고 있으면 **끝날 때까지 기다린다**(최대 10분).
2. 로컬 DB를 온라인 백업(`BackupDatabase`)으로 임시 파일에 복사 → `integrity_check`. 실패하면 어디에도 쓰지 않는다.
3. **이 PC Neosys 폴더에 항상** 쓰고, 등록된 공유폴더마다 한 번씩 더 쓴다. 임시 이름으로 다 쓴 뒤 이름을 바꾼다.
4. 첨부는 새로 생기거나 바뀐 파일만 복사한다. 로컬에서 지운 파일은 `.deleted\<날짜>`로 옮겼다가 보관 일수 뒤 지운다.
5. 보관 일수(기본 7일, 오늘 포함)보다 오래된 `<계정>_yyyyMMdd.db/json`만 지운다.
6. 연결 안 되는 공유폴더는 건너뛰고 다음에 다시 시도한다. 결과는 DB 관리 창에 표시한다.

### 언제 백업하나

- 프로그램: 로그인 후 오늘 백업이 없으면 1분 뒤, 이후 주기(기본 2시간)마다, 대시보드를 닫을 때(종료·로그아웃, 설정으로 끌 수 있음).
- **작업 스케줄러**(선택, `Core/Services/ScheduledBackupTask.cs`, `App/HeadlessBackup.cs`):
  - 켜면 계정마다 작업 `Neosys_Backup_<계정>`을 이 PC 사용자 권한으로 등록한다(관리자 권한 불필요). 주기마다 `NeosysLight.exe --backup <계정>`을 창 없이 실행한다.
  - 놓친 실행은 켜지는 대로 한 번 한다(`StartWhenAvailable`). Windows에 로그인해 있을 때만 돈다(로그인 전에는 공유폴더 접속 권한이 없다). PC가 꺼져 있으면 돌지 않는다.
  - 켜져 있으면 프로그램은 주기 백업을 하지 않고 상태 파일만 1분마다 다시 읽는다.
  - `--backup`은 서버 로그인 없이 `session.json`의 정보로 백업한다. 종료 코드: 0 성공, 1 실패, 2 계정 DB 없음, 3 로그인 기록 없음. 결과는 `backup_status.json`에 `LastBy: scheduler`로 남는다.
  - 개발·점검: `NEOSYS_DB`를 주면 `NEOSYS_FILES`·`NEOSYS_SHARE`(이 PC Neosys 폴더)·`NEOSYS_SHARES`(공유폴더, `;` 구분)도 환경변수로 받는다 — 실제 공유폴더에 쓰지 않는다.

### 예전 구조 옮기기

- 로그인 때(`BackupScheduler.Start`) 백그라운드로 `BackupService.MigrateOldLayout`을 실행한다(잠금 안에서).
- `<공유>\Neosys\<사무소번호>\<계정>\yyyy-MM-dd.*`와 예전 로컬 백업 `%LOCALAPPDATA%\Neosys\backup\Neosys\<사무소번호>\<계정>\`을 새 구조로 옮긴다. 첨부 미러와 `.deleted`도 함께 옮긴다.
- 새 구조에 같은 날짜가 있으면 새 것을 남긴다. 옮긴 뒤 예전 폴더와 빈 상위 폴더는 지운다.

## 3. 용량

| 대상 | 예상 크기 | 7일 보관 시(백업 위치 1곳당, 계정 1명) |
| --- | --- | --- |
| DB(물건·고객 수천 건 + 이력) | 수 MB ~ 수십 MB | 최대 수백 MB — 문제 없음 |
| DB(수만 건, 수년 사용) | 100MB 안팎 | 약 700MB — 디스크 여유만 있으면 문제 없음 |
| 첨부 사진·평면도 | 수천 장이면 수 GB | 미러 방식이라 날짜별로 늘지 않음 |

- 백업 위치 전체 용량 ≈ (계정 수) × (DB 크기 × 7 + 사진 크기). [연결 확인]에서 위치별 남은 공간과 내 백업 크기를 보여 준다.

## 4. 복구(롤백)

구현: `Core/Services/RestoreService.cs`, 테스트 `RestoreServiceTests`.

- `Find`는 이 PC Neosys 폴더와 공유폴더에서 내 계정 날짜 파일을 모은다. `ByDate`는 날짜별로 묶어 늦게 백업한 것부터 시도한다.
- `Restore` 순서:
  1. 잠금을 얻는다. 백업이 돌고 있으면 끝난 뒤 진행한다.
  2. `<계정>.restore-tmp.db`로 복사한 뒤 검사한다: SHA-256 → 무결성 → `LocalDatabase.SchemaVersion`보다 새 버전이면 차단. 실패하면 같은 날짜의 다른 사본을 시도한다.
  3. 지금 DB를 `<계정>.before-restore-<시각>.db`로 남기고 교체한다. 교체에 실패하면 남긴 사본으로 되돌린다.
  4. 첨부는 미러와 그 날짜 이후의 `.deleted`에서 로컬에 없는 파일만 받아 온다.
  5. 프로그램을 다시 시작한다(다시 로그인).
- '복구 전 DB'도 복구 목록에 나온다(되돌리기용). 보관 일수가 지나면 지운다.
- 새 PC 첫 로그인(`LoginWindow.OfferImportAsync`): 계정 DB가 없으면 등록된 공유폴더와 이 PC 폴더에서 찾는다.
  - 공유폴더가 없는 새 PC면 백업이 있는 공유폴더(예: `\\사무실PC\Neosys`)를 고르게 하고, 가져오면 그 폴더를 등록한다.
  - 가져오기에 실패하면 로그인을 멈춘다(빈 DB가 오늘 백업을 덮어쓰지 않게).
- 주의: 복구 뒤 첫 자동 백업이 오늘 날짜 파일을 복구한 내용으로 바꾼다. 복구 직전 DB는 '복구 전 DB'로 남는다.

### 최초 실행 공유 설정 · 공유 정보 알림 (2026-11-02)

이 PC에서 처음 로그인하면(`settings.json`의 `FirstRunSetupDone`이 false) `FirstRunSetup`이 Neosys 폴더·내 백업 폴더를 만들고 공유를 켠 뒤 `ShareInfoWindow`(탭: 공유정보 / 데이터베이스 백업)를 한 번 띄운다.

- 이미 공유돼 있으면 관리자 권한을 묻지 않는다. 공유돼 있지 않으면 UAC 확인 창이 한 번 뜬다(Windows 정책상 생략 불가).
- 네트워크 종류(공용→개인)는 자동으로 바꾸지 않는다. 공용이면 창에 안내하고 [공유설정]에서 사용자가 고른다.
- 취소·실패해도 다시 묻지 않고 창에 이유를 보여 준다. 다시 켜기는 창의 [공유설정]이나 DB 관리 → 네트워크 공유.
- `NEOSYS_DB`로 실행하면(개발·점검) 건너뛴다. 백업 설정 패널은 DB 관리 창과 같은 `BackupSettingsPanel`이다.

## 보안 주의

- 백업에는 고객 이름·연락처가 그대로 들어 있다. `Neosys` 공유에 접속할 수 있는 사람(이 PC에 계정이 있는 사무실 사용자)은 앱 밖에서도 모든 계정의 백업을 열 수 있다. 앱의 "대표만"·"내 폴더만" 제한은 앱 안에서만 효과가 있다.
- 직원끼리 서로의 백업을 못 보게 하려면 백업 파일 암호화가 필요하다(선택, 미구현).
- DB 원본은 공유 밖에 있어 네트워크에서 지우거나 덮어쓸 수 없다.

## 위험·제약

- 같은 계정을 PC 두 대에서 쓰면 두 DB가 따로 바뀌고, 그날 파일은 마지막 백업이 덮어쓴다(합쳐지지 않음). 복구 목록에서 다른 PC가 만든 백업은 주황색으로 보인다. 원칙은 계정당 PC 한 대다.
- 복구는 "그 날짜로 되돌리기"다. 그 이후 입력한 데이터는 사라진다(복구 전 DB는 남겨 둠).
- 보관 일수보다 오래된 시점으로는 되돌릴 수 없다.
- 확인 안 됨(2026-10-29): 실제 [공유설정](관리자 권한·이 PC 설정 변경)과 실제 작업 스케줄러 등록은 개발 중에 실행하지 않았다(스크립트 문법·방화벽 그룹 ID·XML·`--backup` 동작은 확인). 다른 PC에서 `\\PC\Neosys`로 접속하는 것도 확인하지 않았다.

## 남은 결정

1. 보관 기준: "최근 7일(달력)" — 지금 구현. "최근 백업 7개"로 바꿀지.
2. 직원 DB 보기를 대표 외 직원(메뉴권한)에게도 허용할지.
3. 백업 파일 암호화 여부(지금은 없음).
