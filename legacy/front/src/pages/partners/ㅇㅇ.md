# Vendor API 명세

기준 코드
- `Vendor/Controllers/VendorController.cs`
- `Vendor/Models/Vendor.cs`
- `Vendor/Services/VendorService.cs`
- `Shared/ResponseHelper.cs`
- `Shared/Middleware/GlobalExceptionMiddleware.cs`

## Base URL
- `/api/vendors`

## 공통 응답 형식

성공
```json
{
  "success": true,
  "data": {},
  "message": "..."
}
```

실패 (`ResponseHelper.Error` 발생 시)
```json
{
  "success": false,
  "error": {
    "code": "NOT_FOUND",
    "message": "..."
  },
  "traceId": "..."
}
```

- 비즈니스 에러: HTTP `400`
- 서버 예외: HTTP `500`

## 1. 협력업체(Vendor)

### 1) 목록 조회
- Method/Path: `GET /api/vendors`
- Query
  - `vendorId?: number`
  - `offNo?: number`
  - `rtNo?: number`
  - `pageNumber?: number` (default: `1`)
  - `rowsPerPage?: number` (default: `10`)

### 3) 수정
- Method/Path: `PUT /api/vendors/{vendorId}`
- Path
  - `vendorId: number`
- Body (`VendorUpdateDto`): 등록과 동일 스키마

  "message": "협력업체 수정 성공"
}

## 프론트 참고사항
- `POST /api/vendors` 서비스 SQL에서 `bjdCode` 매핑 구문이 `p_vendor_no => @p_bjd_code`로 되어 있어 DB 함수 파라미터와 불일치 가능성이 있습니다.
- 목록 API의 `totalCount`는 현재 구현상 "전체 건수"가 아니라 "현재 페이지에서 조회된 row 개수"입니다.
