# 백엔드 필드 추가 - 테스트 가이드

## 개요
백엔드에 5개 필드(`MvnPsbYn`, `HouseRental`, `PetYn`, `Top`, `PtMemo`)가 추가 완료되었습니다.
프론트엔드는 이미 해당 필드들을 지원하고 있으므로, 연동 테스트를 진행합니다.

---

## 추가된 필드 목록

| 필드명 (Frontend) | 필드명 (Backend) | 설명 | UI 위치 |
|------------------|------------------|------|---------|
| mvnPsbYn | MvnPsbYn | 즉시입주 가능 여부 | 기본정보 > 예정일/기타 정보 > 이전가능 |
| houseRental | HouseRental | 전세자금대출/임대주택 | 기본정보 > 예정일/기타 정보 > 임대주택 |
| petYn | PetYn | 반려동물 허용 여부 | 기본정보 > 예정일/기타 정보 > 반려동물 |
| top | Top | 탑층 여부 | 기본정보 > 예정일/기타 정보 > 탑층여부 |
| ptMemo | PtMemo | 물건 메모 | 기본정보 > 메모 |

## 프론트엔드 연동 현황

### ✅ 완료된 항목

1. **formData 초기화**
   - 파일: `PropertyFormPage.jsx` (라인 119-123, 304-308, 425-429)
   - 5개 필드 모두 formData에 포함됨
   - 기본값 설정 완료 (`mvnPsbYn: 'N'`, `houseRental: 'N'`, `petYn: 'N'`, `top: ''`, `ptMemo: ''`)

2. **UI 입력 필드**
   - 파일: `PropertyFormPage.jsx`
   - 모든 필드가 UI에 구현되어 있음
   - 사용자 입력 가능 상태

3. **등록/수정 API 연동**
   - 파일: `PropertyFormPage.jsx` (라인 666-708)
   - `handleSubmit` 함수에서 formData 전체를 전송
   - 5개 필드가 자동으로 포함됨

4. **API 데이터 변환**
   - 파일: `propertyService.js` (라인 4-21, 64-76, 79-91)
   - `convertKeysToPascalCase` 함수가 자동 변환
   - camelCase → PascalCase 변환 처리됨
   - 예: `mvnPsbYn` → `MvnPsbYn`

5. **조회 API 연동**
   - 파일: `PropertyFormPage.jsx` (라인 220-341)
   - 상세 조회 시 5개 필드 자동 매핑
   - `...detailData` 로 백엔드 데이터 자동 적용

## 테스트 시나리오

### 1. 물건 등록 테스트 (POST /api/property)

#### 테스트 절차
1. 물건관리 메뉴 접속
2. "물건 등록" 버튼 클릭
3. 기본 정보 입력:
   - 물건명: "테스트 아파트"
   - 매물종류: 아파트 선택
   - 거래구분: 매매 체크
   - 주소 입력

4. **새로 추가된 필드 입력**:
   - 메모: "백엔드 필드 추가 테스트" 입력
   - 이전가능: "가능" 선택
   - 임대주택: "예" 선택
   - 반려동물: "가능" 선택
   - 탑층여부: "예" 선택

5. "등록" 버튼 클릭

#### 예상 결과
- 성공 메시지: "물건이 등록되었습니다."
- 네트워크 요청 확인 (개발자 도구):
  ```json
  {
    "PtName": "테스트 아파트",
    "MvnPsbYn": "Y",
    "HouseRental": "Y",
    "PetYn": "Y",
    "Top": "Y",
    "PtMemo": "백엔드 필드 추가 테스트",
    // ... 기타 필드들
  }
  ```

#### 확인 사항
- [ ] 등록 성공 메시지 표시
- [ ] 네트워크 요청에 5개 필드 포함
- [ ] 백엔드에서 200 OK 응답
- [ ] DB에 데이터 저장 확인

## 예상 문제 및 해결방법

### 문제 1: 필드가 null로 저장됨
**원인**: 백엔드 DTO에 필드가 누락되었거나 매핑 오류
**해결**:
- `PropertyCreateDto`, `PropertyUpdateDto`에 5개 필드 추가 확인
- 필드명 대소문자 확인 (PascalCase)

### 문제 2: 400 Bad Request 에러
**원인**: 데이터 타입 불일치 또는 유효성 검증 실패
**해결**:
- DTO 필드 타입이 `string?` 인지 확인
- 필수 필드 검증이 없는지 확인 (모두 선택사항이어야 함)

### 문제 3: 500 Internal Server Error
**원인**: DB 컬럼이 없거나 SQL 에러
**해결**:
```sql
-- 컬럼 존재 확인
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_name = 'pt_sale'
  AND column_name IN ('mvn_psb_yn', 'house_rental', 'pet_yn', 'top', 'pt_memo');
```

### 문제 4: 조회 시 필드가 표시되지 않음
**원인**: Response DTO에 필드가 누락됨
**해결**:
- `PropertyDto` 또는 Response DTO에 5개 필드 추가 확인
