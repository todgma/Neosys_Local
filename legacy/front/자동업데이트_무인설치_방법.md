# 자동 업데이트 — 클릭 없이 무인(silent) 설치로 바꾸기

> 목표: 프로그램 시작 시 스플래시("더 나은 경험을 위해 업데이트 중입니다…")만 보이고, **사용자가 아무것도 클릭하지 않아도** 새 버전이 자동 설치 → 자동 재실행. (은행앱 방식)

---

## 0. 지금 왜 "클릭"이 필요한가 (원인)
현재 흐름(`front/electron/main.cjs`)은 스플래시 → 버전API → 다운로드까지는 자동이지만, 설치 단계에서 **두 번 클릭이 강제**됨:

1. **UAC(관리자 권한) 팝업** — `runInstallerElevated()`가 PowerShell `Start-Process -Verb RunAs`로 실행 → "이 앱이 변경하도록 허용?" 예 클릭 필요. (`main.cjs:682~697`, 호출 `:766`)
2. **NSIS 설치 마법사** — `package.json`의 `nsis.oneClick:false` + `allowToChangeInstallationDirectory:true` → 다음/설치/완료 클릭 필요.

즉 **① 권한상승 제거 + ② 무인 설치 플래그** 두 가지만 바꾸면 클릭이 사라진다.

---

## 방법 A (권장·최소변경) — per-user 무인설치 + `/S`

핵심 아이디어: **관리자 권한이 필요 없는 per-user 설치**로 바꾸면 UAC가 사라지고, NSIS `oneClick + /S`로 마법사가 사라진다. 설치 후 앱은 자동 재실행된다. (Slack·VSCode·은행앱 방식)

### A-1. `package.json` → `build.nsis` 교체
```jsonc
"nsis": {
  "oneClick": true,                       // 마법사 없이 한 번에 설치(+진행바만)
  "perMachine": false,                    // 사용자 폴더 설치 → 관리자/UAC 불필요
  "allowToChangeInstallationDirectory": false,
  "runAfterFinish": true,                 // 설치 후 앱 자동 실행
  "deleteAppDataOnUninstall": false,
  "differentialPackage": true
}
```
> ⚠️ `perMachine:false`(per-user)로 바꾸면 설치 위치가 `%LOCALAPPDATA%\Programs\네오시스\` 로 변경됨. 기존에 **관리자(Program Files)로 설치된 사용자**는 최초 1회 기존 버전 제거 후 재설치가 필요할 수 있음(마이그레이션 주의, 아래 6항).

### A-2. `main.cjs` → 설치 실행을 "무권한 무인"으로 교체
기존 `runInstallerElevated()`(UAC 상승) 대신 아래로 교체:
```js
// 무인(silent) 설치 — per-user라 UAC 불필요. NSIS /S = 완전 무인, oneClick가 설치 후 앱 자동 실행
function runInstallerSilent(installerPath) {
  return new Promise((resolve, reject) => {
    try {
      const child = spawn(installerPath, ['/S'], { detached: true, stdio: 'ignore', windowsHide: true });
      child.on('error', reject);
      child.unref();          // 부모(현재 앱)와 분리 → 앱 종료돼도 설치 계속
      resolve(true);
    } catch (e) { reject(e); }
  });
}
```
호출부(`setupAutoUpdater` 내 `:765~773`)도 교체:
```js
splashStatus('더 나은 경험을 위해 업데이트 중입니다…');
setTimeout(() => {
  runInstallerSilent(installerPath)
    .then(() => { console.log('[Update] 무인 설치 시작'); setTimeout(() => app.quit(), 1500); })
    .catch(async (error) => {
      console.error('[Update] 설치 실행 오류:', error);
      isUpdating = false;
      await openInstallerFolderAndNotify(installerPath); // 실패 시에만 수동 폴백
    });
}, 800);
```
> 실행 중인 exe는 잠겨 있으므로, 설치 시작 직후 `app.quit()`로 앱을 종료해 파일 교체가 되게 함. oneClick 설치기가 설치 완료 후 새 버전을 자동 실행(`runAfterFinish`).

### A-3. 스플래시 문구(은행앱 느낌)
`splashStatus(...)` 메시지를 단계별로:
- 확인: `"업데이트 확인 중…"`
- 다운로드: `"더 나은 경험을 위해 업데이트 중입니다… (n%)"` (이미 `splash:progress` 퍼센트 수신)
- 설치: `"거의 다 됐어요. 잠시만 기다려 주세요…"`

### A-4. 빌드/배포
- 빌드: `npm run electron:build` → `dist-electron`에 `*-Setup-<버전>.exe` 생성
- 서버 버전API(`/api/version/latest`)의 `downloadUrl`을 새 Setup exe로 갱신 → 다음 실행부터 무인 적용.

**결과: 사용자는 스플래시만 보고, 클릭 0회로 업데이트 완료 후 앱이 새로 뜬다.**

## 방법 B (정석) — electron-updater 도입
장기적으로는 커스텀 다운로드 대신 **electron-updater**(NSIS 차분 업데이트·서명검증·자동 재실행)로 가는 게 안정적.

### B-1. 설치
```
npm i electron-updater
```
### B-2. `package.json` publish(generic 피드) — 서버에 파일 3종 배치
```jsonc
"build": {
  "publish": [{ "provider": "generic", "url": "https://다운로드서버/updates/" }],
  "nsis": { "oneClick": true, "perMachine": false, "runAfterFinish": true }
}
```
빌드 시 생성되는 `latest.yml` + `*.exe` + `*.blockmap` 을 위 URL 폴더에 업로드.

### B-3. `main.cjs`
```js
const { autoUpdater } = require('electron-updater');
autoUpdater.autoDownload = true;
autoUpdater.on('checking-for-update', () => splashStatus('업데이트 확인 중…'));
autoUpdater.on('download-progress', (p) => splashStatus(`더 나은 경험을 위해 업데이트 중입니다… (${Math.floor(p.percent)}%)`));
autoUpdater.on('update-not-available', () => closeSplashAndStart());
autoUpdater.on('error', () => closeSplashAndStart(1000));
autoUpdater.on('update-downloaded', () => {
  splashStatus('거의 다 됐어요…');
  autoUpdater.quitAndInstall(true /*isSilent*/, true /*forceRunAfter*/); // 무인 설치 + 자동 재실행
});
app.whenReady().then(() => autoUpdater.checkForUpdates());
```
`quitAndInstall(true, true)` = **완전 무인 + 설치 후 자동 실행**. per-user면 UAC도 없음.

> 장점: 차분(delta) 다운로드로 빠름, 서명/해시 검증 자동, 재실행까지 보장.
> 단점: 서버에 `latest.yml` 규격 파일 배치 필요(기존 버전API와 병행/대체).

## 5. 코드 서명(중요) — SmartScreen/백신 경고 방지
- 미서명 exe는 무인 설치여도 Windows SmartScreen/백신이 **최초 실행·다운로드 시 경고**를 띄울 수 있음(이건 클릭 유발 요인).
- **정식 해결**: 코드사이닝 인증서(EV 권장)로 서명. electron-builder `win.certificateFile`/`certificatePassword` 또는 서명 서비스.
- 서명 없으면 무인설치는 되더라도 **SmartScreen "추가 정보→실행"** 클릭이 남을 수 있음 → 사내 배포면 화이트리스트/정책 배포로 우회.

## 6. per-user 전환 시 마이그레이션 주의
- 기존 사용자가 **Program Files(관리자)로 설치**돼 있으면, per-user 새 설치본과 **두 벌 공존**할 수 있음.
- 대응: 이번 한 번은 공지 후 기존 버전 수동 제거 → 신규(무인) 설치, 이후부터 무인 자동. 또는 최초 무인설치 시 기존 설치 제거 스크립트 포함.

## 7. 안전장치(이미 있음/권장)
- `mandatory`(강제 업데이트) 플래그 이미 지원(`getLatestVersion`) — 무인설치와 궁합 좋음.
- 다운로드 파일 MZ 헤더 검증(`isValidExeFile`) 유지.
- 설치 실패 시에만 폴더 열고 수동 안내(`openInstallerFolderAndNotify`) 폴백 유지.
- 네트워크 실패/버전API 무응답 시 즉시 앱 시작(`closeSplashAndStart`) — 오프라인에서도 앱 실행 보장.

## 요약 (가장 빠른 적용)
1. `package.json` → `nsis.oneClick:true`, `perMachine:false`, `allowToChangeInstallationDirectory:false`, `runAfterFinish:true`
2. `main.cjs` → `runInstallerElevated`(UAC) 를 `runInstallerSilent`(`/S`, 무권한)로 교체 + 호출부 수정
3. 스플래시 문구 "더 나은 경험을 위해 업데이트 중입니다…"
4. 빌드 후 서버 `downloadUrl` 갱신
→ **클릭 0회 무인 업데이트.** (SmartScreen 완전 제거는 코드서명 필요)

- 서버 버전 API: `/api/version/latest` (`downloadUrl`, `mandatory`)
